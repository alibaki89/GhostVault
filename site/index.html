GhostVault

Free, private and encrypted cloud storage, powered by your own GitHub repositories. GhostVault protects your files on your computer, stores encrypted pieces online, and brings them back when you need them.

What it is

Free up your disk, store your files privately

GhostVault is a free-to-use desktop app for encrypted cloud storage using private GitHub repositories that you control. Select a file, and GhostVault divides it into 512 KiB chunks, encrypts them on your device, and uploads those pieces to your repositories. Only after checking that the remote data is in place does it remove the original from your computer.

When you need the file back, Restore retrieves its encrypted chunks, checks their integrity, decrypts them, and reconstructs the original without overwriting existing files. Files appear as ghosts in the desktop gallery until you restore them.

No GhostVault subscription or GhostVault-hosted account is required. You use your own GitHub account and private repositories. GitHub's storage, bandwidth, rate limits and acceptable-use rules still apply: free-to-use does not mean unlimited cloud storage, and GitHub is not a substitute for a separate backup.

GhostVault runs on Windows, macOS and compatible Linux desktops. You can download a ready-to-run application or install from source with Python 3.11 or newer. Prepare an independent backup of important files before depending on any cloud storage service.

Inside the project

How GhostVault is put together

GhostVault is a Python desktop application with a Tk-based graphical interface and a command-line entry point. Its storage engine, cryptography, file handling, and GitHub transport are separate modules. It operates from your computer; there is no GhostVault-operated storage server, account service, or subscription backend.

Four parts working together

  • The application and vault: the gallery shows a record for each ghost, while the vault coordinates ghosting, restoration, repository placement, and recovery. Operations that could take time run outside the UI thread.
  • Encryption and file handling: original files are read in 512 KiB chunks and encrypted locally with AES-256-GCM using a separate random key per file and a fresh nonce per chunk. Authentication binds chunks to their file and position.
  • GitHub storage: encrypted chunks are stored as Git objects in the user's private repositories using GitHub's API. Distributed placement spreads a file's pieces across eligible repositories; consolidated placement keeps that file's pieces in one selected repository. Neither option makes redundant copies.
  • Local state and recovery: owner-only local records contain the decryption keys and the map of chunk locations. Encrypted recovery files and an optional encrypted repository backup can preserve this information if the data folder is lost, but they do not replace missing encrypted chunks.

Designed around safe state changes

Because ghosting removes the local original, the critical work is deciding when deletion is allowed. GhostVault records its steps in a durable journal, reads back the remote Git tree to verify what was committed, and samples uploaded data before removing an unchanged original. On restore, it verifies and writes the complete file before cleaning up its remote references. Interrupted operations can be resumed or rolled back on restart.

Its network layer handles retries, uncertain GitHub responses, API limits, and paced writes. Authentication tokens are kept in the operating system's credential manager or supported keychain where available; file keys remain in the protected local GhostVault data directory. See the architecture documentation and cryptography and recovery guide for implementation details.

Get started

Install and run

Windows

Use the installer to add GhostVault to your Start menu, or extract the portable ZIP and run GhostVault.exe. The bundled application does not need a separate Python installation. Windows may show a SmartScreen warning for unsigned downloads. Verify the checksum and consult the Windows guide before proceeding.

macOS

Choose the disk image for your Mac's processor: Apple Silicon (macOS 11+) or Intel (macOS 10.15+). Open the DMG and drag GhostVault to Applications. These disk images are not notarized, so macOS may block the first launch. The macOS guide explains how to review the warning.

Linux

The prebuilt Linux archive targets x86-64 with glibc 2.35+ and a graphical X11/XWayland session. After downloading it, open a terminal in the folder containing the file:

tar -xzf GhostVault-1.0.0-linux-x86_64.tar.gz
cd GhostVault-1.0.0-linux-x86_64
./GhostVault/ghostvault

You can also run ./install.sh from the extracted directory to install it for your user. See the Linux guide for desktop integration and keychain requirements.

Run from source · Windows, macOS and Linux

Get the source ZIP or clone the repository. Install Python 3.11 or newer with Tkinter, then create a virtual environment and install the local source. From the extracted source root:

python3 -m venv ghostvault-env
ghostvault-env/bin/python -m pip install .
ghostvault-env/bin/ghostvault

On Windows PowerShell, use py -3 -m venv ghostvault-env, .\ghostvault-env\Scripts\python.exe -m pip install ., then .\ghostvault-env\Scripts\ghostvault.exe. This is for supported desktop environments, not an assurance that the software runs on every device or mobile operating system. Complete source instructions.

The idea

Why split the file up

GitHub repositories are designed for source code, not general-purpose cloud drives. GhostVault divides a file into pieces of 512 KiB so it can encrypt and handle each piece independently, then store the ciphertext in repositories you control.

You can use distributed placement to spread a file's chunks across multiple repositories, or consolidated placement to keep that file's chunks in one repository. Neither mode creates redundant copies: losing a repository containing a needed piece can make the file unrecoverable.

Every chunk is encrypted locally with authenticated encryption (AES-256-GCM). The files' content and names aren't uploaded in plaintext. GitHub can still see usage patterns, ciphertext sizes and activity. Its storage limits and terms continue to apply regardless of chunk size.

How it works

Ghosting a file

When you ghost a file, GhostVault encrypts its pieces locally, uploads them, checks the GitHub references and samples of the uploaded content, records the recovery information, and removes the original only after the safety checks succeed.

Every file gets a fresh random encryption key and every chunk a unique nonce. The local record stores the keys and locations needed to reconstruct the file. Never treat GitHub as your only backup for important data.

The pieces

Where everything lives

Two parts work together. Encrypted chunks live in your private GitHub repositories. The keys and chunk map live in the local GhostVault data folder. You can also create an encrypted recovery file or opt into encrypted repository backup, so loss of the computer need not mean loss of the keys.

Remote storage contains encrypted chunks, not readable original files. The local records are essential: losing them without a separate recovery file or encrypted repository backup can make your ghosts unrecoverable. Keep your recovery passphrase or backup key somewhere safe.

How it works

Restoring a file

Restoring downloads the encrypted pieces, verifies their integrity and authentication, and reconstructs the file. GhostVault checks the full result before publishing the restored file, without overwriting a file that already exists at that name.

The encrypted chunks are removed from the active repository branches only after the restored file is safely published. Git history may still retain earlier encrypted versions; restoring is not secure erasure.

Setup

Connecting your caves

A cave is a private GitHub repository where GhostVault stores encrypted chunks. Create one or more empty private repositories for GhostVault, open Settings → GitHub, then add each repository address and a token that can write to it. GhostVault verifies that the repository is private and that it can access it.

GitHub

A fine-grained GitHub personal access token should be restricted to only the repositories you select and granted Contents: Read and write. A classic token with the repo scope also works, but offers broader access. Tokens are kept in the operating system's credential store where available, not in GhostVault's own settings files.

Distributed placement spreads pieces across selected repositories. Consolidated placement stores a file's pieces together. Both depend on GitHub continuing to retain those encrypted pieces. Start with the official setup instructions and respect GitHub's terms and size limits.

Storage

Where your data is kept

Your local data folder holds file records and their keys, settings, encrypted previews, and logs. It is separate from the application installation and is not deleted by uninstalling GhostVault.

  • Windows: %LOCALAPPDATA%\GhostVault.
  • macOS: ~/Library/Application Support/GhostVault.
  • Linux: ~/.local/share/ghostvault by default, or $XDG_DATA_HOME/ghostvault when configured.

You can change this location with the --data-dir option. The data folder is sensitive: someone who can read its keys may be able to restore your ghosts.

Good to know

What is protected, and what to mind

What is protected

Chunks use AES-256-GCM authenticated encryption before upload. Repository readers cannot directly read your file's contents or original filename from ciphertext alone. Remote metadata and traffic patterns still reveal when and how much you store.

Keep your recovery options safe

File keys are in the local data folder. In Settings → Recovery, create an encrypted recovery file protected by a passphrase, or enable encrypted repository backup and write down the recovery key. Without a working recovery option, losing your computer or its data folder may permanently lose access to your ghosts.

Understand the limits

GhostVault removes the local original only after a verified upload, but a ghost isn't an independent backup of that file. Encrypted chunks are not duplicated across repositories; repository deletion, account restriction, network trouble or a compromised computer can prevent recovery. Restored chunks may remain in Git history. Keep separate copies of important files, and read Security & limitations.

Technical report · GhostVault 1.0.0

The complete system design and implementation report

GhostVault includes a 16-page technical report covering the design decisions, implementation, security boundaries, failure handling, verification methods, and measured performance of version 1.0.0. It explains not only how files are encrypted, but how the program decides when an original or a remote chunk may safely be removed.

What you can read in the report

  • Architecture and data formats: desktop interface, vault, GitHub transport, Git objects, local records, encryption keys, and journal states.
  • Security and recovery: threat model, authenticated encryption, key handling, recovery bundles, repository backups, and where protection ends.
  • Failure handling: crashes, network interruptions, misleading API responses, verification before deletion, and restoring without overwriting existing files.
  • Tests and performance: simulated GitHub testing, randomized failure injection, workload measurements, GitHub request costs, and known limitations.

Read the technical report (PDF) ↗

The report's LaTeX source, diagrams, and measurement data are included in the repository. The full application source code and test suite are public as well.

How to interpret the verification results

The report describes a 663-test suite and a simulated stress run of 3,200 operations, 1,273 simulated crashes, and 7,736 injected network faults without data loss observed in those runs. These are test results, not a guarantee against data loss. Its verification chapter records the Linux environment available when the report was written; subsequent Windows and macOS release builds were carried out separately. The report is not an independent security audit or a certification of every platform.

For practical usage, start with the installation guide. For the limitations that matter before storing valuable files, read Security & limitations. GitHub limits and policies apply, and a ghost is never a substitute for an independent backup.
